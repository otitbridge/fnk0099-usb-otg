# 検証結果

検証日：2026-11-11。対象はFNK0099 Rev 1.1 / N16R8、UIAPduino V1.4内蔵SFC、AT-PDCASTCC08、MacのUSB-UART接続です。物理操作は製作者が行い、判定はUARTログと照合しています。結果はこの組合せでの実績です。

## 現在の確認範囲

| 試験 | 結果 |
|---|---|
| 直結・USB列挙・HID受信 | 成功 |
| 修正版の12入力・左右30秒以上保持・3入力・部分解放 | 成功 |
| 押下中の切断で全解放、再接続 | 修正後に成功 |
| 再接続3回・RESET再起動3回 | 成功 |
| USB-UART給電を切って戻す | 記録環境で1回成功。リセット線の影響は未分離 |
| Host側USB-Cプラグ反転 | 成功。Device側の向きは固定 |
| 30分連続稼働 | 保留・未完了 |

現在の実装はコミット `6cca133` に対応します。実機試験BINはコミット前に作成したため、起動ログの版表示は `9cb49b4-dirty` です。[修正版のハッシュ記録](evidence/p5-fix-firmware-2026-11-11.json)で識別してください。コミット後の再ビルドでは埋め込み版情報などによりBINハッシュが変わる場合があります。

## P1：Host単体起動

USB Host・HIDドライバーともESP_OKで起動し、40秒の取得中に35秒間にわたる8回の稼働ログを確認しました。[結果](evidence/p1-result-2026-11-11.json)・[ログ](evidence/p1-uart-2026-11-11.log)。

## P2：直結確認

2026-11-11、ユーザーがAT-PDCASTCC08でSFCコントローラーを既設OTGへ直結し、UARTでマウスIF0（protocol=2）・キーボードIF1（protocol=1）の検出と、その後のHost稼働継続を確認しました。[結果](evidence/p2-result-2026-11-11.json)・[UARTログ](evidence/p2-direct-uart-2026-11-11.log)。

ログの `Unexpected device` はP1実装が機器接続を通知する文言で、列挙失敗を示しません。このP2時点ではVID/PIDやエンドポイント照合、入力受信は未実施でした。

## P3：記述子・初期レポート

2026-11-11、VID:PID=1209:D004、Low-Speed、キーボードIF1・EP82（Interrupt IN、8バイト、10ms）を実機で照合しました。SET_PROTOCOL(BOOT)・SET_IDLE(0)・受信開始はすべてESP_OKで、全解放の8バイトレポートを受信しました。[結果](evidence/p3-result-2026-11-11.json)・[ログ](evidence/p3-enumeration-2026-11-11.log)。

ホスト上の変換テストは[ビルド手順](build.md#変換ロジックのテスト)に従って実行できます。12ボタン対応、同時入力、部分・全解放、不正レポートを検査します。これは実機ボタン試験とは区別します。

## P4：12ボタン単独入力

全12ボタンを指定順に識別し、各押下後に全解放へ戻ることをUARTで確認しました。実測押下時間は220〜300msで、長押し試験とは区別します。[結果](evidence/p4-result-2026-11-11.json)・[ログ](evidence/p4-buttons-2026-11-11.log)。

## P5：長押し・部分解放

左32.81秒、右36.09秒の保持と解放を確認しました（合格基準は各30秒以上）。右＋Y＋Bを5.18秒保持し、Bだけ離した後も右＋Yが6.77秒継続、最後に全解放へ戻りました。[結果](evidence/p5-hold-result-2026-11-11.json)・[ログ](evidence/p5-hold-2026-11-11.log)。

初回の切断試験ではマスクの全解放は成功しましたが、HID後処理エラーにより再接続を認識できませんでした。[失敗記録](evidence/p5-disconnect-failed-2026-11-11.json)。切断コールバック内でインターフェースを閉じるよう修正し、書き込みと初期認識を確認済みです。修正後の再試験では、切断時の全解放、インターフェースclose=ESP_OK、再列挙、右・Bの押下と解放に成功しました。[再試験結果](evidence/p5-disconnect-retry-2026-11-11.json)。抜去時の `EP command error: ESP_ERR_INVALID_STATE` は残っていますが、この試験では復帰を妨げませんでした。発生原因は未確定として記録します。

## P6：再接続の繰り返し

全解放での抜き差し3回すべてで、再認識・右とBの押下と解放に成功しました。接続中の空きヒープは各回360,668バイトでした。[結果](evidence/p6-reconnect-result-2026-11-11.json)。抜去時のEPエラーは継続し、1回はURBエラーと不正レポートのログも出ましたが、マスクは0のまま、次の接続・入力は成功しました。

## P6：Host再起動と確認範囲

P6のRESET再起動3回はすべて成功しました。毎回Host初期化・SFC再認識・右とBの押下と解放を確認し、この3回にはエラーログはありません。[結果](evidence/p6-restart-result-2026-11-11.json)・[ログ](evidence/p6-restart-2026-11-11.log)。

今回のP1〜P6の実施した機能試験は成功しました。切断処理修正後の最終版でも、12ボタン・長押し・同時押しの回帰試験を完了しました（詳細は以下）。抜去時のEP／URB診断ログの原因は未確定です。USB-C両端の全組合せ・長時間耐久・接続時のボタン保持・電圧測定は未確認です。

## 修正版の回帰確認

コミット `6cca133` の実装と一致する書き込み済みファームで、12ボタンすべての押下・解放、左56.34秒・右30.55秒の保持、右＋Y＋Bを5.38秒、B解放後の右＋Yを3.06秒、最後の全解放を確認しました。左の初回28.73秒は基準未達として残し、再試験で30秒以上を確認しています。回帰試験中にエラーログはありませんでした。[結果](evidence/regression-final-2026-11-11.json)・[ログ](evidence/regression-final-2026-11-11.log)。

## 電源断後の復帰

SFCのOTG接続を保持し、USB-UARTの給電を抜いて戻す試験1回で、Host起動・SFC再認識・右とBの押下と解放に成功しました。UARTの消失から再オープンまで約13.98秒でした。[結果](evidence/cold-start-2026-11-11.json)・[ログ](evidence/cold-start-2026-11-11.log)。電圧は未測定で、UART再オープン時のリセット線の影響も分離していないため、この記録環境での復帰確認として扱います。

## USB-Cプラグの向き

AT-PDCASTCC08のFNK0099側プラグを180度反転しても、SFC再認識・右とBの押下と解放に成功しました。内部側プラグの向きは固定のため、確認範囲はHost側の両向きです。[結果](evidence/usb-c-orientation-2026-11-11.json)・[ログ](evidence/usb-c-orientation-2026-11-11.log)。

## 30分連続稼働試験（保留）

ユーザーの意向により保留しました。記録は停止済みで、合格・完了には数えません。[保留記録](evidence/endurance-deferred-2026-11-11.json)。再開時は新たに30分以上の記録を取得します。

## 残るEP／URBログの重要度

**軽微（暫定）** と評価します。修正後に残るログはUSB抜去時に観測され、切断時の全解放、再接続3回、RESET再起動3回で操作復帰を確認しています。修正後の試験では入力残留・クラッシュ・復帰不能は確認していません。原因が解明済み、または無害と保証されたという意味ではありません。

修正前の「再接続できない問題」は重大な機能不具合として区別します。通常接続中にもログが発生する、入力停止・入力残留・クラッシュ・復帰不能を伴う場合は、重大へ評価を見直します。

電源やCCを原因と決めつけず、Host起動→デバイス起動→列挙→クラス要求→入力受信の順で切り分けます。既存UIAPduinoプロジェクトは変更しません。
