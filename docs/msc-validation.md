# USBカードリーダー・microSDの読み書き検証

既存のSFCコントローラー用HID検証とは別に、FNK0099のUSB-OTG端子に接続したカードリーダー経由で、microSD 1GBのファイル読み書きを検証します。実装・試験は段階ごとに止めて結果を共有します。

## 接続と実装方針

- PC → USB-UART → FNK0099：給電、書き込み、115200 baudのログ。
- FNK0099 → USB-OTG → USBカードリーダー → microSD 1GB。
- ESP-IDF 5.5.0を維持し、MSC検証用のPlatformIO環境 `fnk0099-msc` を追加しました。MSCドライバーは `espressif/usb_host_msc` 1.3.0に固定しています。
- USB Host → MSC（BOT / Transparent SCSI）→ FatFs / VFS → ファイル操作の構成にします。
- 起動や再接続によって書き込み試験を自動実行せず、明示的なUART操作で開始します。

参考：[ESP-IDF 5.5 MSCサンプル](https://github.com/espressif/esp-idf/tree/v5.5/examples/peripherals/usb/host/msc)、[USB Host仕様](https://docs.espressif.com/projects/esp-idf/en/v5.5/esp32s3/api-reference/peripherals/usb_host.html)。

## 検証段階と合格条件

| 段階 | 内容 | 合格条件・停止点 |
|---|---|---|
| 1 | 既存ファームでUSB記述子取得 | MSC / SCSI / BOT、Bulk IN・OUTを確認して停止 |
| 2 | MSC専用環境の実装・ビルド | ビルド成功、変更レビュー後に停止。実機書き込みは次の区切り |
| 3 | 実機起動・メディア情報・読み取り | 容量取得、マウント、既知ファイルの内容・サイズ・SHA-256一致を確認して停止 |
| 4 | 小さいテキストの新規作成 | 同期・クローズ・再オープン後に完全一致を確認して停止 |
| 5 | 既知パターンの1MiBファイル | アンマウント・再マウント後にサイズ・SHA-256一致。可能ならPCでも照合して停止 |
| 6 | 安全な取り外し・再接続3回、アンマウント後のRESET3回 | 毎回再認識・読み取り成功、クラッシュや継続的なヒープ減少なし |

当初の7項目の計画では、現在は3番「メディア確認」まで完了し、4番「読み取り」は未完了です。本書では実機起動・メディア確認・読み取りを段階3にまとめています。マウント成功は既知ファイルの内容・SHA-256照合の完了を意味しません。

各段階でエラーが出た場合は先へ進まず、失敗したAPI、エラーコード、所要時間を整理します。速度は参考値とし、データ一致と再接続後の保持を主な合否基準にします。

## データと公開情報の扱い

- 2026-11-17、ユーザーよりSDに残したいデータはないと確認しました。自動フォーマット無効・既存ファイルを上書きしない方針は維持します。
- 自動フォーマットを無効にし、マウント失敗時は停止します。生セクターの書き換えは行いません。
- 試験用ファイルは専用の新規名を使い、既存ファイルと衝突した場合は停止します。
- 初回検証に書き込み途中の抜去・電源断は含めません。
- 生のUART・ビルド・書き込みログやローカル設定は、Git対象外の `.local/msc-validation/` に保存します。
- 公開する証跡は必要な項目だけを抽出します。個人名、ホームディレクトリ、機器固有のシリアル番号、実UARTポート名、MACアドレス、SD内の既存ファイル名・内容を含めません。
- VID/PID、USBクラス、エンドポイント、容量、検証用データのハッシュ、エラーコードは公開可能な技術情報として記録します。
- コミット前に差分と追跡対象を確認します。履歴の書き換え・リモートへの公開はこの検証作業に含めません。

段階1の結果共有でいったん停止し、その後、既存データの保持が不要であるとの回答を受けて段階2へ進みました。

## MSC専用ファームの操作

`fnk0099-host` は引き続きHID用で、環境指定のない `pio run` もHID用です。MSC環境は別の `sdkconfig`・ビルド出力を使い、`CONFIG_FNK0099_MSC_PROBE` によって `src/msc_main.c` を選択します。依存マニフェストとロックは両環境で共有します。

```sh
pio run -e fnk0099-msc
```

次の実機段階で使用する書き込み・モニターコマンドです。`YOUR_UART_PORT` はローカルで確認したポートに置き換えます。シリアルポートを使用するプログラムは同時に1つにします。

```sh
pio run -e fnk0099-msc -t upload --upload-port YOUR_UART_PORT
pio device monitor --port YOUR_UART_PORT --baud 115200
```

起動後、MSC認識時にメディア情報取得とマウントを試みます。マウント失敗時は自動で再試行・フォーマットせず、ログを整理して停止します。現在のファームはファイルへの書き込み操作を実装していません。物理的な書き込み保護を設定するものではありません。

UARTでは次のコマンドをCRまたはLFで送信できます。ファイル操作と接続・切断の後処理は1つのタスクで順番に実行し、コールバック内では操作しません。

| コマンド | 動作 |
|---|---|
| `help` | コマンド一覧 |
| `status` | 接続・マウント状態、容量、空きヒープ、稼働時間 |
| `mount` | 未マウントの認識済みメディアを手動マウント |
| `ls` | ルートディレクトリの項目数だけを確認。既存の名前はログに出さない |
| `read` | ルートの `PROBE.TXT` を公開フィクスチャと比較し、一致時にサイズとSHA-256を出力 |
| `unmount` | アンマウントし、成功時に `SAFE_TO_REMOVE` を出力 |

### 既知ファイルの読み取り確認

PCでカードを開ける場合、`tests/fixtures/msc/PROBE.TXT` をSDルートにコピーし、安全に取り外してFNK0099へ戻します。同名ファイルがある場合は上書きせず停止します。カードのフォーマットやコピーはこの実装段階では行っていません。

- ファイル長：30バイト（末尾はLF、BOMなし）。
- SHA-256：`96a1296c1224e6471cd1e6bfc3577a7b91622e19c95d42df2928e1bb6d531d9d`。
- `read` の合格ログ：`READ_PASS bytes=30 sha256=...`。
- ファイルなしは `READ_NOT_VERIFIED`、内容・長さの不一致は `READ_MISMATCH` とし、読み取り検証の合格に数えません。

フィクスチャを用意できない場合も、容量・マウント・ルート読み取りまでは確認できます。その場合、既知データの照合は未完了として残し、ユーザーと次の手順を決めます。

USB速度は `FULL (12Mbps)` / `LOW (1.5Mbps)` / `OTHER` と区別します。機器の文字列記述子はシリアル番号を含むため出力しません。切断時はVFS・MSCデバイスの順に解放し、後処理失敗時は試験を止めてRESETを求めます。これらの実機動作は次の段階で確認します。

## 段階2の結果（2026-11-17）

MSC専用環境と読み取り用コマンドを実装し、以下を確認しました。

| 確認 | 結果 |
|---|---|
| `pio run -e fnk0099-msc` | 成功。コンパイラーの警告・エラーなし |
| `pio run -e fnk0099-host` | 成功。コンパイラーの警告・エラーなし |
| ビルド対象ソース | MSCは `msc_main.c`、HIDは `main.c`。生成BINの起動文字列でも切り替えを確認 |
| 既存 `tests/test_report.c` | `-Wall -Wextra -Werror` でビルド・実行し、12入力、同時入力、部分・全解放、不正レポートを合格 |
| 公開読み取りフィクスチャ | 30バイトと上記SHA-256をホスト側で確認 |
| 公開対象の確認 | 差分空白検査と、ホームパス・実UARTポート・MAC・シリアル番号・鍵・トークンのパターン検査を通過。生ログ、生成sdkconfig、BINはGit対象外 |

MSC用BINは341,744バイト、SHA-256は `798c362b94b8197438677911d677a48be13a7e819bddc609d42dbc86c5e3ca54` です。これはこの時点のローカル生成物の識別値で、コミット・再ビルド時には埋め込み版情報などにより変わる場合があります。

MSCドライバーはESP-IDF 5.5.0でビルドできることを確認しました。1.3.0の採用理由には、[公式変更履歴](https://components.espressif.com/components/espressif/usb_host_msc/versions/1.3.0/changelog)に記載されたブロックサイズ検証の修正も含みます。

**判定：実装・ビルド段階は完了。実機への書き込み前で停止。** 実機でのMSC初期化、容量・ファイルシステムの取得、UARTコマンド、ファイル照合、切断処理は未検証です。SDの初期化・ファイル作成・コピーも実施していません。次は段階3の実機書き込み・容量取得・マウント確認です。

## 段階3の途中結果：実機書き込み・マウント（2026-11-17）

ユーザーの実機書き込み指示を受け、`fnk0099-msc` をUSB-UART経由で書き込みました。ブートローダー・パーティションテーブル・アプリの3領域で `Hash of data verified.` を確認し、アップロードは成功しました。アプリBINのサイズ・SHA-256は段階2の記録と一致しています。

書き込み後、UARTを20秒間取得しました。取得には再起動からのログが含まれます。書き込み終了時のRTSリセットとUARTを開く際のリセット線の影響は分離していません。

|---|---|
| MSC起動 | `MSC_HOST_READY` |
| カードリーダー | `14cd:1212`、`FULL (12Mbps)` |
| メディア初期化 | `install_device: ESP_OK`、100ms |
| セクター数・サイズ | 1,966,079セクター、512バイト/セクター（ドライバーの報告値） |

**判定：実機書き込み・MSC初期化・容量取得・マウントは成功。ここで停止。** 現在は読み取り用MSCファームで、カードをマウントした状態で待機しています。自動フォーマットやファイルの作成・変更は行っていません。UARTコマンドの操作試験、ルートディレクトリの読み取り、既知ファイルの内容・SHA-256照合、書き込み試験、再接続試験はまだ実施していません。段階3全体の合格とはせず、次の区切りで読み取り確認へ進みます。

生のアップロードログ・起動ログは `.local/msc-validation/` に保持し、この公開用記録には必要な技術情報だけを抽出しています。
