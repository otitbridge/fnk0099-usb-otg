# 既知の制約・問題の切り分け

## 抜去時のEP／URB診断ログ：軽微（暫定）

物理的なUSB抜去時に `EP command error: ESP_ERR_INVALID_STATE` が残っています。繰り返し試験では1回、`Enqueue URB error` と `invalid_report` も記録しました。原因は未確定です。

修正版では切断時の全解放、再接続3回、RESET再起動3回、右・Bの操作復帰を確認しました。試験範囲では入力残留・クラッシュ・復帰不能を認めないため、機能への影響を軽微と暫定評価しています。無害と保証するものではありません。

通常接続中の発生、入力停止・入力残留・クラッシュ・復帰不能を伴う場合は、重大へ評価を見直します。[再接続の証跡](evidence/p6-reconnect-result-2026-11-11.json)。

## 修正済み：切断後に再接続できない

初期の受信版ではHIDインターフェースのcloseをアプリケーションタスクへ遅延していました。ドライバー1.0.1の切断処理とのタイミングが合わず、無効なハンドルのエラーと再接続不能を観測しました。これは重大な機能不具合として扱います。

切断コールバック内でcloseを完了するよう変更し、アプリケーション側には状態の全解放通知だけを送る構成で復帰を確認しました。現在残る抜去時のEP／URBログとは区別します。[失敗記録](evidence/p5-disconnect-failed-2026-11-11.json)・[修正後](evidence/p5-disconnect-retry-2026-11-11.json)。

## 適用範囲

- UIAPduinoキーボード版のVID/PID・IF番号に限定しています。
- 最大6入力。UIAPduinoが送信しない入力は復元できません。
- Host側USB-Cの両向きは確認済みですが、内部側は固定です。
- 30分連続稼働は保留。接続時保持・サスペンド復帰・VBUS電圧・CC回路の適合性は未確認です。
- 電源断後の復帰はUART記録環境で確認済みですが、UART再オープン時のリセット線の影響は分離していません。
- 10msのポーリング間隔から、操作全体の遅延を保証することはできません。

## 切り分け

| 症状 | 最初に確認する項目 |
|---|---|
| 起動ログがない | USB-UART端子、ポート名、115200 baud、他のモニターとの競合 |
| Host初期化に失敗 | 実行ファーム、USBコンソール設定、初期化エラー |
| SFCが検出されない | OTG端子、通信ケーブル、Hostログ。給電不能と即断しない |
| 列挙後に受信開始しない | VID/PID、IF1、SET_PROTOCOL／SET_IDLEの結果 |
| 入力の解釈がおかしい | 8バイトRAW、Usage ID、マスク、6入力制限 |
| 再接続できない | 修正版か、closeの結果、抜去前後のログ |

原因確認前にVBUSへの強制給電やCC抵抗の変更を行わないでください。電圧測定が必要なら、USB-C端子内に直接プローブを差し込まず、適切な測定治具を使います。
