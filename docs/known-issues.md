# 既知の制約・問題の切り分け

## SFC/HID抜去時のEP／URB診断ログ：軽微（暫定）

物理的なUSB抜去時に `EP command error: ESP_ERR_INVALID_STATE` が残っています。繰り返し試験では1回、`Enqueue URB error` と `invalid_report` も記録しました。原因は未確定です。

修正版では切断時の全解放、再接続3回、RESET再起動3回、右・Bの操作復帰を確認しました。試験範囲では入力残留・クラッシュ・復帰不能を認めないため、機能への影響を軽微と暫定評価しています。無害と保証するものではありません。

通常接続中の発生、入力停止・入力残留・クラッシュ・復帰不能を伴う場合は、重大へ評価を見直します。[再接続の証跡](evidence/p6-reconnect-result-2026-11-11.json)。

## SFC/HID修正済み：切断後に再接続できない

初期の受信版ではHIDインターフェースのcloseをアプリケーションタスクへ遅延していました。ドライバー1.0.1の切断処理とのタイミングが合わず、無効なハンドルのエラーと再接続不能を観測しました。これは重大な機能不具合として扱います。

切断コールバック内でcloseを完了するよう変更し、アプリケーション側には状態の全解放通知だけを送る構成で復帰を確認しました。現在残る抜去時のEP／URBログとは区別します。[失敗記録](evidence/p5-disconnect-failed-2026-11-11.json)・[修正後](evidence/p5-disconnect-retry-2026-11-11.json)。

## SFC/HIDの適用範囲

- UIAPduinoキーボード版のVID/PID・IF番号に限定しています。
- 最大6入力。UIAPduinoが送信しない入力は復元できません。
- Host側USB-Cの両向きは確認済みですが、内部側は固定です。
- 30分連続稼働は保留。接続時保持・サスペンド復帰・VBUS電圧・CC回路の適合性は未確認です。
- 電源断後の復帰はUART記録環境で確認済みですが、UART再オープン時のリセット線の影響は分離していません。
- 10msのポーリング間隔から、操作全体の遅延を保証することはできません。

## Bolt抜去時の転送・EP診断ログ：評価保留

HIDドライバー1.1.0のBolt再接続1回目で、抜去前後60msに転送失敗4行、アプリの `INPUT_ERROR` 4行、`EP command error: ESP_ERR_INVALID_STATE` 4行を記録しました。4IFのclose・状態解除・再認識・受信再開、Aと左クリックの復帰は成功しました。再認識後のエラー、受信欠落、不正入力、押下残留、パニック、追加の再起動はありませんでした。

2回目も4IFと固定入力の復帰を確認しましたが、抜去時50msにURB投入エラー4行、キーボード・マウスの0バイト不正入力各1行、EPエラー4行がありました。再認識後のエラー・不正入力・受信欠落・押下残留・パニック・追加の再起動はありませんでした。初回と異なる診断のため、3回目の前に監視を停止しました。

3回目も再認識・入力受信・全解放を確認し、抜去時には2回目と同種の10行がありました。指定したA操作1組に対して2組を観測しましたが、ユーザーが2回押した（押し直した）と回答し、実際の操作と照合できました。3回目も機能復帰を確認済みとし、当初の1回操作条件との違いと監視判定を記録に残しています。

物理RESET後の復帰は別試験で3回合格し、各回の警告・エラー・受信欠落・押下残留は0でした（3回目は操作不明の初回試行を除外し、再試験で確認）。この結果はレシーバー抜去時の診断の原因・影響を解消するものではありません。

現在はレシーバー再接続の機能復帰を3回確認した段階です。エラーなしの合格条件には届かず、診断ログの原因・影響を評価中です。各回のUARTセッションは分かれており、3回すべてが合格した連続試験ではありません。既存SFC/HIDの診断ログとは検証対象・ドライバー版・観測内容が異なるため、同じ原因と断定しません。通常接続中にも発生する、入力停止・残留・クラッシュ・復帰不能を伴う場合は、機能不具合として扱います。

## SFC/HID回帰：SFCを挿したままの起動で列挙失敗

2026-11-17の回帰確認で、デバイス記述子取得またはアドレス設定中にEP0転送が失敗しています。SFCを挿したまま起動した場合は、次のどの条件でも失敗しました。

- 1台目・2台目のどちらでも
- 公開SFC v1.0.0への書き換え後
- 従来Host HID 1.0.1、Arduino／ESP-IDF 4.4.7のUSB専用版
- C to Cケーブル直結

1台目・C to Cの前後比較では、元Host 1.1.0と比較版の両方で、接続済み起動が9/9失敗しました。一方、Hostを起動してから挿すと、両版で各1/1認識しています。

**回避手順：** SFCを抜いてHostを起動し、`HOST_READY` の後に全解放で挿します。この手順で、Host 1.1.0の12ボタン単独入力に合格しました。ただし成功は1回だけです。また、以前は旧ケーブル構成でHost先行接続も失敗しています。電源投入時に挿したままの起動、保持・部分解放・切断復帰は未確認です。根本原因は未確定で、接続順序・ケーブル・個体・電気的条件のどれかに断定できる結果ではありません。

## MSCの適用範囲と同期

- 確認済みはカードリーダー `14cd:1212`、microSD 1GB、FAT16の組合せです。別機器・別ファイルシステムは未検証です。
- 31バイト・1MiBの新規作成、再マウント・Mac照合、再接続3回・RESET3回を確認しました。長時間稼働、全容量書き込み、書き込み中の抜去、電源断耐性は未検証です。
- 上記のMSC最終6試行で警告・エラーはありませんでした。前述のEP／URB診断ログはHID試験の観測です。
- `fsync` はESP-IDF 5.5.0のVFSからFatFsの `f_sync` へ進みます。MSCドライバー1.3.0の `CTRL_SYNC` は成功を返す実装で、SCSI SYNCHRONIZE CACHEは発行しません。APIの成功だけでは電源断時の保持を保証できません。
- 起動時の自動書き込み・自動フォーマットは行いません。同名ファイルは拒否し、途中で失敗したファイルも自動削除しません。再確認は読み取り用コマンドで行います。

詳細は[MSC操作手順](msc-usage.md)と[MSC検証結果](msc-validation.md)を参照してください。

## 切り分け

| 症状 | 最初に確認する項目 |
|---|---|
| 起動ログがない | USB-UART端子、ポート名、115200 baud、他のモニターとの競合 |
| Host初期化に失敗 | 実行ファーム、USBコンソール設定、初期化エラー |
| SFCが検出されない | OTG端子、通信ケーブル、Hostログ。給電不能と即断しない |
| 列挙後に受信開始しない | VID/PID、IF1、SET_PROTOCOL／SET_IDLEの結果 |
| 入力の解釈がおかしい | 8バイトRAW、Usage ID、マスク、6入力制限 |
| HIDで再接続できない | 修正版か、closeの結果、抜去前後のログ |
| MSCマウントに失敗 | 環境名、メディア情報、ファイルシステム、エラーコード。自動フォーマットしない |
| `WRITE_EXISTS` / `BULK_EXISTS` | 同名ファイルの存在。新規作成を繰り返さず `verify-write` / `verify-1m` を使う |
| MSC照合に失敗 | 既知ファイルの準備、サイズ・SHA-256、読み取りエラー。原因確認まで次の書き込みへ進まない |
| `CLEANUP_FAILED` | 後処理の失敗ログを保存し、RESETしてから状態を再確認 |

原因確認前にVBUSへの強制給電やCC抵抗の変更を行わないでください。電圧測定が必要なら、USB-C端子内に直接プローブを差し込まず、適切な測定治具を使います。
