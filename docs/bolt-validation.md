# Boltレシーバー：K950・M750対応

対象は、ペアリング済みのロジクールK950とM750を1つのBoltレシーバー経由でFNK0099のUSB-OTGへ接続する構成です。USB-UARTは給電・書き込み・115200 baudの操作とログに使います。ブランチは `feat/bolt-keyboard-mouse` です。

## 段階と現在の状態

| 段階 | 内容 | 状態 |
|---|---|---|
| 1 | 専用環境・USB認識・HIDインターフェース・レポート記述子の取得 | 合格（2026-11-17） |
| 2 | 固定操作で入力形式を照合し、キー・修飾キー・マウス移動・ボタン・ホイールを解釈 | 基本入力は合格。K950固定キー操作、M750の3ボタン・4方向移動・縦ホイール両方向を確認 |
| 3 | 同時操作・保持と解放・再接続・RESET・ログ負荷の検証 | 同時保持・片側解放は合格。再接続3回の機能復帰を確認（3回目はA押し直しを照合済み）。抜去時ログは評価保留。RESETは3回合格（3回目は再試験） |
| 4 | 既存SFCの実機回帰確認、公開証跡・操作手順の確定 | 主ブランチのHostでは接続済み起動の列挙失敗が続く。最初の列挙を約1秒遅らせる試作では、接続済み起動が10/10で認識した（未統合）。1台目・C to CのHost先行接続では、Host 1.1.0で12ボタン単独入力に合格。保持・部分解放・切断復帰は未実施。[引き継ぎ資料](sfc-troubleshooting.md) |

実機の物理操作や判断が必要な区切りで結果を共有します。ビルド成功後は書き込み・起動確認まで続けます。記述子の取得だけではK950・M750の入力対応完了とはしません。

## 段階1の結果（2026-11-17）

専用環境・既存SFC環境・MSC環境の3つをビルドし、すべて成功しました。コンパイラーの警告・エラーはありません。既存のSFC変換、小さいファイルの新規作成・同期・再オープン、1MiB生成とPython照合のホストテストも成功しています。

USB-UART経由で `fnk0099-hid` を書き込み、ブートローダー・パーティションテーブル・アプリのハッシュ検証に成功しました。UART取得には再起動からのログを含みます。UARTを開く際のリセット線の影響は分離していません。

| 項目 | 観測結果 |
|---|---|
| レシーバー | `046d:c548`、Full-Speed 12Mbps |
| IF0 | Boot subclass / Keyboard protocol、Interrupt IN `0x81`、レポート記述子59バイト |
| IF1 | Boot subclass / Mouse protocol、Interrupt IN `0x82`、レポート記述子158バイト |
| IF2 | subclass/protocol `0/0`、Interrupt IN `0x83`、ベンダーHID++記述子54バイト |
| IF3 | subclass/protocol `0/0`、Interrupt IN `0x84`、Digitizer・拡張記述子429バイト |
| 全4インターフェース | 最大パケット64バイト、記述子上のポーリング間隔1ms、open/startすべてESP_OK |

IF0はReport IDなしの8バイトキーボード形式です。IF1のマウスReport ID `0x02` は、16ボタン分・符号付き16bitのX/Y・符号付き8bitの縦ホイール/横パンを定義し、IDを含め9バイトです。IF1にはConsumer Controlなど別IDも含まれます。これは段階1時点での記述子の解釈です。M750の物理操作は段階2の結果に分けて記録しています。1msの記述値から操作全体の遅延は保証しません。

取得した標準の[キーボード記述子](../tests/fixtures/hid/bolt-keyboard-report-desc.hex)・[マウス記述子](../tests/fixtures/hid/bolt-mouse-report-desc.hex)を、今後の解釈処理のテスト用に保存しました。[公開結果JSON](evidence/bolt-discovery-2026-11-17.json)には全4IFの記述子ハッシュと実機試験BINの識別情報を記録しています。アプリBINは286,208バイト、SHA-256は `6f7a83836c44180a1f3b3075fd49b9c297875dfc2406dcd23d93ae2d2d9cb635` です。生成時は作業中のソースで、ベースコミットは `4348f79` です。

**判定：記述子調査まで合格。入力対応は開発中です。** UART取得は終了してポートを閉じました。次工程は固定操作による入力照合と解釈処理です。既存SFCのドライバー更新後の実機回帰も残っています。

## 実装方針

- 既存のSFC専用 `fnk0099-host` と別に `fnk0099-hid` を設けます。既定環境は変更しません。
- キーボード・マウス・その他HIDの複数インターフェースを開き、状態を個別に扱います。
- マウスのホイールや追加ボタン、Report IDを確認するためReport protocolを使います。Boot形式の3バイト固定として推測しません。
- USB文字列（シリアル番号を含む）は出力しません。HID++などのベンダー入力ペイロードもダンプしません。
- HIDドライバーは1.1.0に固定します。レポート記述子取得とclose/disconnectの修正を含みます。[公式変更履歴](https://components.espressif.com/components/espressif/usb_host_hid/versions/1.1.0/changelog)。ESP-IDFは5.5.0です。
- 依存マニフェストは3環境で共有します。過去のSFC実機合格はHIDドライバー1.0.1での結果です。更新後はビルド確認に加えて実機回帰が必要です。

FNK0099側でのペアリングやLogi Options+相当の設定機能は実装しません。ペアリング済みのレシーバーから届くUSB HID入力を受信します。

## 段階2の実装と検証

記述子調査はコミット `39b1264` に保存しました。その後、`src/hid_input.c` に上限付きのHID記述子解析・入力解釈を追加しました。Report IDごとの入力長、Keyboardのキー配列/ビット、Mouseのボタンと相対X/Y・縦ホイール・横パンを記述子から取得します。未対応の記述子は推測して読みません。

- キー状態は256 Usage分のビット列で保持し、変化した押下・解放だけを出力します。無通信や同一レポートを理由にキーを解放しません。
- ロールオーバーは警告と回数を記録し、最後の有効なキー状態を保持します。次の有効レポート・切断・転送エラーで状態を更新します。
- マウス移動・ホイールは20msを目安に加算して出力し、同じ差分が連続しても省略しません。ボタン変化時はその前の移動量と分けて出力します。
- 切断・転送エラー・不正な入力では保持状態を解除します。再接続前のレポートを識別するため、インターフェースごとに世代番号を付けています。
- 接続/切断・UARTコマンドは入力用と別のキューで受けます。入力キューが溢れた場合は古いレポートを破棄して状態を解除し、`INPUT_DROPPED` を出して試験不成立とします。
- ベンダーHID++・Digitizerの入力ペイロードは解釈・出力しません。Consumer Control・System Controlなど今回の対象外のReport IDもキー/マウス状態へ混ぜません。特殊機能・LED制御・文字配列変換は未対応です。

取得済みの2記述子を使ったホストテストで、修飾キー・部分解放・ロールオーバー、符号付き16bit移動量、16ボタン分、縦横ホイール、Report ID・入力長、不正な記述子を確認しました。切り詰めとサイズ/個数の変異入力もAddressSanitizer・UndefinedBehaviorSanitizer付きで実行し、成功しました。[テスト手順](build.md#bolt入力解釈のホストテスト)。ホストテストを物理入力・USB通信の合格として扱いません。

入力解釈版をビルドして実機に転送し、書き込みハッシュ検証に成功しました。K950でA、左Shift＋A、右矢印の固定操作を照合しました（結果は以下）。M750の基本操作も別の区切りで照合しました（結果は以下）。

### 起動・コマンド過多の再試験（2026-11-17）

新版は4インターフェースで受信開始し、IF0は1入力レポート・9フィールド、IF1は4入力レポート・20フィールドとして解析できました。最初の監視補助スクリプトは開始コマンドを重複送信し、コマンドキューの過多でファームがリセットしました。この試行は失敗として保存しています。

監視側の開始送信を1回にし、ファーム側も過多コマンドを `COMMAND_BUSY` で拒否するよう修正しました。64個の `status` 連続送信で4件を拒否し、エラー・パニック・受信欠落は0、追加の再起動はありませんでした。開始から6,244msの最終 `status` も受信しました。[実装・再試験の公開記録](evidence/bolt-decoder-preparation-2026-11-17.json)に失敗理由・修正・合格した再試験をまとめています。

書き込み済みアプリBINは291,168バイト、SHA-256は `0fbb220495fb7d25249281ec0d95ffb41516dc4151a7a6fff96fa368e92fa24b` です。`39b1264` をベースに入力解釈を追加した、コミット前の実機試験物です。この起動・再試験の時点では、物理的なキー・マウス操作の合格はまだ判定していませんでした。

### M750物理操作の試験手順

K950の試験と同じ書き込み済みファームで実施します。UARTは継続して開き、30秒の入力キャプチャを25秒ごとに延長し、全体を最大10分で終了します。操作順序は次のとおりです。

1. 左クリックの押下・解放。
2. 右クリックの押下・解放。
3. ホイールを押し込む中央クリックの押下・解放。
4. ボタンを離した状態で右 → 左 → 奥 → 手前へ移動。
5. 縦ホイールを奥へ数刻み、次に手前へ数刻み回す。

左・右・中央を `buttons=1 → 0 → 2 → 0 → 4 → 0` の6遷移として照合します。移動は各方向の主軸成分を50カウント以上観測し、X正・X負・Y負・Y正の順序を確認します。移動距離・DPI・速度の校正ではありません。縦ホイールは正方向と負方向を確認します。

全項目の観測後に `stop`・`status` を実行し、入力欠落・不正入力・押下状態の残留・警告・エラーを確認します。終了連絡時に未観測の項目があれば、判定を保留してログを確認します。横ホイール・サイドボタン・同時操作・長時間稼働はこの試験に含めません。

同じ入力解釈版で、上記の順序どおりに物理操作とログを照合しました。

| 試験 | 結果 |
|---|---|
| 左・右・中央ボタン | `1 → 0 → 2 → 0 → 4 → 0` の6遷移が一致。押下保持は左1,160ms・右1,130ms・中央680ms |
| 4方向移動 | 右（X正）→ 左（X負）→ 奥（Y負）→ 手前（Y正）の順に確認。各主軸50カウント以上を観測 |

| 受信と出力 | 1,214件のマウスレポートを解釈し、20msを目安にまとめた525行のマウスログを出力 |

縦ホイールは両方向の観測成立時点で自動的に記録を停止したため、上記の数値はユーザーが回した全刻み数ではありません。4方向のカウントも各方向の検出閾値に到達した時点の値で、全移動量・距離・DPIの測定とは区別します。

**判定：M750の3ボタン・4方向移動・縦ホイール両方向は合格。段階2の基本入力確認を完了しました。** [公開結果JSON](evidence/bolt-mouse-input-2026-11-17.json)に、6つのボタン遷移・方向検出の時刻・ホイールの観測値・最終状態を保存しました。横ホイール・サイドボタン・同時操作・再接続・RESET・長時間稼働は未検証です。次は段階3の同時操作・保持と解放・再接続・RESETを検証します。

## 段階3：同時操作・保持と解放の手順

基本入力の実装と結果はコミット `47e9e31` に保存しました。実機は同じ入力解釈版（上記のBINハッシュ）を使用し、再ビルド・再転送せずに続けます。

1. K950の右矢印を押したままにします。
2. M750の左ボタンも押したまま、両方を45秒以上保持します。その間、マウスを左右へゆっくり動かし続けます。
3. 右矢印だけを離します。マウス左ボタンは押したまま、さらに5秒ほど左右へ動かします。
4. マウス左ボタンを離します。
5. Aを押して離し、その後マウス右ボタンを押して離します。

合格条件は、両方の保持を30秒以上観測し、その間のマウス移動が左右それぞれ50カウント以上・20秒以上の期間にわたること、右矢印の解放時にマウス左ボタンが維持され、以後3秒以上の保持と50カウント以上の移動があることです。最後のA・右クリックと全解放、受信欠落・不正入力・ロールオーバー・警告・エラーの有無も確認します。45秒・5秒はユーザー操作の目安で、判定にはUART上の観測時刻を使用します。

UARTを開いたままキャプチャを更新し、最大10分で終了します。操作成立後は `stop`・`status` を実行します。この試験は再接続・RESET・長時間稼働の合格には数えません。

### 同時保持・片側解放の初回結果（2026-11-17）

初回は35秒以上の操作目安で案内しました。操作順序と片側解放は確認できましたが、両方の同時保持は24,380msで、事前の合格基準30,000msに届きませんでした。**初回は時間条件未達とし、合格には数えません。**

右矢印を離した時点でもマウス左ボタンは保持され、以後18,160msの保持と移動を確認しました。続くAと右クリック、最後の全解放も一致しています。キーボード421件・マウス2,787件を解釈し、受信欠落・不正入力・ロールオーバー・警告・エラー・パニックは0、最終空きヒープは329,576バイトでした。

開始前に22件のキー遷移がありました。独立した生ログ確認で、本試験の右矢印押下以降の4キー遷移とは分けました。公開記録には準備操作の件数のみを残し、指定外のキー値は含めません。UART取得は終了してポートを閉じました。[初回結果JSON](evidence/bolt-simultaneous-attempt1-2026-11-17.json)に条件未達の理由と確認できた動作を記録しています。

再試験では時計やタイマーで両方を45秒以上保持するよう案内しました。合格基準は30秒のままです。待機中の準備操作と混同しないよう、全解放状態からの右矢印押下を本試験の開始として扱います。

同じ書き込み済みファームで再試験し、以下を確認しました。全解放状態からの右矢印押下を開始点とし、それ以前の準備操作は本試験から分けました。

| 試験 | 結果 |
|---|---|
| 右矢印と左ボタンの同時保持 | 74,510ms。合格基準30,000ms以上 |
| 同時保持中のマウス移動 | 左右それぞれ50カウント以上を確認。3,221件の移動ログが74,110msにわたって継続 |
| 右矢印だけを解放 | マウス左ボタンは保持されたまま |
| 以後の左ボタン保持と移動 | 5,340ms。合格基準3,000ms以上。225件の移動ログを確認 |
| 最後の入力復帰 | 左ボタン解放 → A押下・解放 → 右クリック・解放の順序が一致 |
| 最終状態 | キャプチャ停止、押下キー0、ボタン0、受信欠落0、不正入力0、ロールオーバー0 |
| 警告・エラー・パニック | なし。最終空きヒープ329,576バイト |

UARTセッション全体ではキーボード272件・マウス10,438件を解釈しました。このカウンターは試験開始前の準備操作も含みます。準備中のキー遷移2件・マウスログ90件は本試験の順序照合から除外し、公開記録には件数だけを残しました。

**判定：同時保持・片側解放・入力復帰は合格。** [再試験結果JSON](evidence/bolt-simultaneous-attempt2-2026-11-17.json)に固定入力の遷移・保持時間・移動の集計・最終状態を保存しました。初回の時間条件未達の記録も保持しています。UART取得は正常終了し、ポートを閉じました。

今回のログ負荷で受信欠落はありませんでしたが、長時間稼働や全条件での処理能力を保証する試験ではありません。段階3は再接続・RESETの試験が残っています。既存SFCのドライバー更新後の実機回帰も未実施です。

### 再接続3回の試験手順

同時保持・片側解放の結果はコミット `21d9e47` に保存しました。同じ書き込み済みファームを使用し、USB-UARTを開いたまま次の操作を1回ずつ行います。

1. キーとマウスボタンをすべて離します。
2. USB-UARTの給電を維持し、USB-OTG側のBoltレシーバーだけを抜いて5秒待ちます。
3. 同じレシーバーを戻し、5秒待ちます。
4. K950のAを押して離します。
5. M750の左ボタンを押して離します。

各回、4IFすべての `DISCONNECT ... close=ESP_OK` と `STATE_CLEAR`、同じVID/PIDの再認識、4IFの受信再開、IF0/IF1のレイアウト解析、Aと左クリックの順序・全解放を照合します。最後にキャプチャを停止して状態を取得し、受信欠落・不正入力・警告・エラー・パニックの有無と空きヒープを確認します。

- **最初の列挙を約1秒遅らせる版：** 電源を切った起動もUARTリセット起動も、10/10で認識しました。原因は最初の列挙が早すぎることで、一度失敗するとSFCが応答しなくなります。
- **未実施：** 遅延版での保持・部分解放・切断復帰・物理RESETと、主ブランチへの取り込み。

現在のFNK0099はBolt用ファームではなく、試作の遅延版SFC Host（`rcv1-pp-d1000`）です。主ブランチのビルドではありません。1台目SFCをユーザー報告のC to C直結で接続中で、UART監視は終了しています。[引き継ぎ資料](sfc-troubleshooting.md)に条件比較・成果物・再開手順をまとめ、各試行の詳細は[調査履歴](history/sfc-troubleshooting-2026-11-17.md)へ分離しました。過去のSFC合格結果を現構成の合格として扱いません。

## 調査ファームの操作

```sh
pio run -e fnk0099-hid
pio run -e fnk0099-hid -t upload --upload-port YOUR_UART_PORT
pio device monitor --port YOUR_UART_PORT --baud 115200
```

`YOUR_UART_PORT` はローカルで特定したUSB-UARTポートへ置き換えます。モニターと書き込みツールを同時に開かないでください。

起動時にUSBのVID/PID、速度、インターフェース、エンドポイント、各HIDレポート記述子を取得します。入力受信を開始しますが、生の入力ログは既定で無効です。記述子から解析した標準キーボード・相対マウスの入力を解釈します。文字配列に変換せず、キーUsage ID・押下/解放・修飾キーと、ボタン・移動量・ホイール量を扱います。

| UARTコマンド | 動作 |
|---|---|
| `status` | IF別の受信数・解釈数・除外数・不正数・ロールオーバー数・開始状態、欠落数、空きヒープ |
| `capture` | 30秒限定で解釈したキー遷移・マウス入力を出力。実行中の再送は30秒の期限を延長 |
| `stop` | 入力ログを停止して状態を出力 |

入力ログには固定の試験操作だけを使用します。試験ではAの押下・解放、Shift＋A、矢印、左右・中クリック、移動、ホイール上下などを段階別に実施します。操作とレポートを対応づけてから解釈処理を実装します。30秒制限は調査用です。長時間試験の合格判定とは分けます。

生ログ・ポート名・機器固有情報・一時解析結果はGit対象外の `.local/bolt-validation/` に保存し、公開記録は必要な技術情報と固定の検証操作だけを抽出します。
